# 自动阅卷系统

基于 AI 的自动化阅卷工具，支持截图识别、AI 评分、自动填分全流程。

## 功能特点

- **截图识别**：自动截取题目区域，调用 AI 视觉模型识别和评分
- **智能评分**：支持多家 AI 服务商（OpenAI、智谱 AI、通义千问、豆包、百度千帆、科大讯飞、小米 MiMo 等），自定义评分标准
- **接口配置选项卡**：界面分「阅卷主界面 / 接口与模型 / 评分标准 / API 配置」四个选项卡，且每个选项卡内的模块都可折叠（状态自动记忆）。API 配置页可新建、复制、编辑、删除多套自定义 API（名称/服务商/base_url/API Key/额外请求头/模型列表），保存到 config.json；「接口与模型」页直接选择配置好的供应商与模型即可开始阅卷
- **思考模式**：自动为支持思考模式的模型（MiMo、Qwen3、DeepSeek-R1、QwQ）启用深度推理，提高评分准确率
- **结构化输出**：AI 以「最终得分 + 反馈信息」分隔符格式输出，分数提取不受反馈内容干扰
- **多区域框选**：支持框选多个答案区域（适用于填空题），自动拼接为带编号标签的一张图，防止答案错位
- **区分印刷与手写**：提示词指导 AI 区分答题卡印刷文字和学生手写内容，只以手写部分为评分依据
- **自动生成评分标准**：支持从截图或上传题目图片，由 AI 自动生成评分标准
- **AI 评分记录**：自动收集每次评分记录（含截图、AI 反馈、多模型校验各模型分数），启动程序时自动加载历史记录，双击任意记录即可弹窗查看截图与完整评分详情
- **快捷优化建议**：输入优化想法，AI 分析后直接生成新评分标准
- **自动填分**：基于坐标点击的自动填分，支持分数输入框、提交按钮、下一题按钮
- **空白卷检测**：基于截图灰度波动识别空白答卷，支持直接数值滑块调节和手动标记空白卷自动校准阈值
- **批量处理**：支持批量阅卷，可设置总份数并自动停止
- **评分失败自动停止**：API 超时或异常时自动停止阅卷，不会误填 0 分
- **超时与重试可调**：「API 配置 → 请求设置」可自由设置 API 响应超时（5~600 秒，默认 60）与失败重试次数（0~5 次，默认 1），改完立即生效并随 config.json 保存；重试仍失败则终止本轮阅卷，不会误填 0 分
- **多模型交叉校验**：同一题由主模型与 1~2 个附加模型并行批改，分数一致直接放行；不一致时自动进入第三轮校验（独立仲裁模型 / 主模型参考前几轮分数重评 / 直接选取首轮最高分），最终分数照常进入填分与记录流程，降低单模型误判风险
- **关键事件通知**：API 无响应、任务完成、三轮校验分数均不一致时，自动弹窗提醒并发送 Windows 系统通知，人不在电脑前也能及时知晓

## 系统架构

```
自动阅卷系统/
├── 上层GUI.py              # 主界面程序（启动入口：阅卷主界面 / 接口与模型 / 评分标准 / API 配置 四个选项卡）
├── 自动阅卷系统GUI.py      # 核心模块（流程编排）
├── modules/
│   ├── __init__.py
│   ├── 自动截图模块.py      # 截图区域选择、多区域框选与截图保存
│   ├── 自动评分模块.py      # AI 评分（支持多种模型、思考模式）
│   ├── 多模型校验模块.py    # 多模型交叉校验（并行批改→分数比对→第三轮校验）
│   ├── 系统通知模块.py      # Windows 系统通知（关键事件弹窗+气泡提醒）
│   ├── 自动填分模块.py      # 自动填分（坐标点击）
│   ├── 规则调优模块.py      # 评分记录模型与调优引擎（标记/偏差分析逻辑保留）
│   └── 评分数据库模块.py    # SQLite 评分记录持久化
├── .gitignore
├── requirements.txt
└── config.json             # 运行时配置文件（已从 Git 排除）
```

## 使用方法

### 启动程序

```bash
python 上层GUI.py
```

### 配置步骤

1. **配置接口（首次使用）**：切到「API 配置」选项卡 → 点「新建」→ 选择服务商、填写 base_url / API Key → 点「获取模型列表」（或「手动添加」）→ 点「保存配置」/「保存并应用（返回主界面）」
2. **选择接口与模型**：切到「接口与模型」选项卡，在「接口配置」下拉框选择已保存的配置，在「模型」下拉框选择模型（下方「当前连接」会显示生效的 base_url、脱敏 Key、接口类型与思考模式）
3. **设置评分标准**：切到「评分标准」选项卡，手动输入评分细则，或在该页底部「快捷优化建议」中让 AI 优化；也可通过菜单栏「生成」自动生成
4. **截图配置（菜单栏 → 截图配置）**
   - **选择截图区域**：单区域框选，适用于大多数题型
   - **多区域框选（填空题）**：分别框选每个答案空位，自动拼接为带编号标签的图片
     - 操作：拖拽框选 → Enter 确认 / Backspace 撤销 / Esc 取消
   - 选择分数输入框、提交按钮、下一题按钮位置
   - 「阅卷主界面 → 阅卷参数」的「准备状态」会显示各项是否已设置
5. **开始阅卷**：回到「阅卷主界面」点击「开始单题阅卷」，单题模式处理当前题目，批量模式按设定份数循环处理
   - 批量模式下，运行区会实时显示「平均用时 X/份 · 预计剩余 Y · 预计完成 HH:MM:SS」：依据已处理份数的实际平均用时估算，随进度动态收敛（未设定总份数时只显示平均用时）

> 界面说明：每个选项卡顶部都有「全部展开 / 全部折叠」按钮，点击各模块标题栏也可单独展开 / 收起；折叠状态自动记忆到 config.json，重启后保持。

### 接口配置（API 配置选项卡）

界面顶部的「API 配置」选项卡用于集中维护自定义 API，可保存多套配置随时切换：

1. **左侧列表**：显示全部已保存配置（含服务商），蓝色高亮行为当前使用中的配置；支持「新建 / 复制 / 删除 / 设为当前使用」
2. **右侧详情**（修改后点「保存配置」写入 config.json）：
   - **配置名称**：「接口与模型」页下拉框里显示的名字（如「kcdey 网关」）
   - **服务商**：OpenAI / 智谱 AI / 通义千问 / 豆包 / 百度千帆 / 科大讯飞 / 小米 MiMo / 自定义等；智谱、千帆、讯飞使用专用接口，base_url 自动禁用
   - **base_url / API Key / 额外请求头JSON**：OpenAI 兼容网关填写完整地址（通常以 `/v1` 结尾）
   - **思考模式 / 接口类型**：与「接口与模型」页的下拉一致（自动 / 关闭 / 开启；自动判断 / Chat Completions / Responses API）
   - **模型列表**：「获取模型列表」自动拉取 `/models`，也可「手动添加」；双击列表项设为默认模型
3. **保存与生效**：「保存配置」写入文件；「保存并应用（返回主界面）」保存后立即切换为当前使用，并在「接口与模型」页的下拉框中选中
4. 「接口与模型」页的「获取模型列表」会把拉取结果同步保存到当前接口配置，重启后仍在
5. **请求设置（全局，左下角）**：
   - **响应超时(秒)**：5~600，默认 60；对所有接口配置、评分/生成标准/模型列表/优化建议等全部 API 调用生效
   - **失败重试次数**：0~5，默认 1（0 = 不重试）；次数不含首次请求，重试间隔为 1s、2s、4s… 递增
   - 修改后立即生效并保存；「接口与模型」页的「当前连接」行会同步显示当前超时与重试设置（旧配置缺这两个字段时使用默认值）

> 兼容说明：旧版 config.json（顶层 provider/api_key/model/base_url 等字段）首次加载时会自动合成为「XX（默认）」配置，原有配置不丢失；新增的 `api_profiles` / `active_profile` 字段与旧字段并存，顶层字段仍与当前使用中的配置保持同步。

### 空白卷检测

- **滑块调节**：「阅卷主界面 → 阅卷参数」中的「空白阈值」滑块范围 0~40，值越高越容易判定为空白
- **测试空白检测**：截取当前区域，显示灰度波动和判定结果
- **标记空白卷**：翻到空白答题卡页面，点击「标记空白卷」，程序自动识别灰度波动并设置阈值（+2 余量）

### AI 评分记录

1. 每次评分后自动收集记录（含截图、AI 反馈、多模型交叉校验各模型分数）；启动程序时自动从数据库加载历史记录（最多显示最近 1000 条）
2. 列表直接展示每条记录的序号、题号、AI 分数、用时、模型与交叉校验结果标签（一致 / 三轮·仲裁 / 三轮·重评 / 降级等）
3. 记录栏右侧显示**本次评分总用时**：运行中实时刷新、结束后定格；单条记录用时（截图→AI 评分）也会在列表中展示，未单独记录时回退显示交叉校验总用时
4. 鼠标悬停记录行可快速预览分数、反馈和截图
5. **双击任意记录**打开独立详情窗口：左侧显示答题截图（可一键用系统程序打开原图），右侧分标签页显示：
   - **评分详情**：题号、模型、评分时间、评分用时、AI 最终分数、人工标注（如有）
   - **多模型校验**：每个模型各自的分数、耗时、失败原因，第三轮校验方式与结果；未启用交叉校验时会明确提示
   - **AI 反馈**：该次评分的完整反馈文本
   - **评分标准**：该次评分使用的标准
6. 需要重新开始时点击「清空记录」：清空列表并删除数据库中的全部评分记录（清空前自动备份到 `scores.db.bak`，截图文件不受影响）

### 多模型交叉校验（可选）

在「接口与模型」选项卡的「多模型交叉校验」区块中：

1. 勾选「启用多模型交叉校验」，并至少启用「模型B / 模型C」中的一个
2. 每个槽位先选「接口配置」：
   - **复用主模型**：使用主模型的网关连接（base_url / API Key 自动留空复用，主模型为智谱/百度/讯飞时不支持复用）
   - **选择已保存的配置**：自动填充该配置的 base_url / API Key，模型下拉框切换为该配置的模型列表
   - 下方 base_url / API Key 输入框仍可手动微调
3. 附加模型统一使用 OpenAI 兼容接口（专用 SDK 服务商的配置不能用于交叉校验，运行前会给出明确提示）
4. 按需设置：
   - **分数容差**：0 = 必须完全一致才放行；也可放宽到允许相差 1~10 分
   - **第三轮模式**：`自动选择`（配了仲裁模型就独立仲裁，没配就主模型参考重评）/ `主模型参考重评` / `独立仲裁模型` / `选取最高分`（不额外调用模型，直接采用首轮各有效分数中的最高分，偏宽松）
   - **仲裁模型**：第三轮独立重评用（可选）
5. 评分流程：多模型同题并行批改 → 分数一致直接放行 → 不一致自动进入第三轮校验 → 最终分数照常进入填分、记录与数据库（评分库保存完整交叉校验明细，可在 CSV 导出中查看）

异常降级规则：附加模型失败会自动跳过降级；仲裁/重评失败则回退采用主模型第一轮分数，日志会提示人工注意。「选取最高分」模式不调用额外模型，仅在首轮有效分数中取最高值，不存在第三轮调用失败的情况。

### 通知提醒

以下三种情况会自动弹出窗口，并通过 Windows 系统通知（任务栏气泡）提醒，人不在电脑前也能及时知晓：

- **API 无响应**：阅卷因 API 超时/连接失败终止（不会误填 0 分），通知中附带错误详情
- **任务完成**：单题阅卷完成（含评分结果）/ 批量阅卷达到设定份数
- **三轮校验分数均不一致**：多模型交叉校验时，第三轮结果与首轮各模型分数均不相同，通知中列出各轮分数，建议人工复核

## AI 输出格式

评分指令要求 AI 按以下结构化格式输出：

```
最终得分：4分
===反馈开始===
第1题得2分，第2题得1分，第3题得1分。
===反馈结束===
```

- 第一行为得分（唯一分数提取来源）
- 反馈信息用于调试，不会干扰分数提取
- 有分隔符时禁止从全文兜底匹配，防止误提

## 故障排除

| 问题 | 解决方案 |
|------|----------|
| API 超时 | 在「API 配置 → 请求设置」调大响应超时或重试次数（默认 60 秒 / 1 次）；仍失败则终止本轮阅卷（不会误填 0 分），请检查网络或网关 |
| 评分提取错误 | AI 以结构化格式输出，第一行为得分，反馈信息不会干扰 |
| 空白卷误判 | 点击「标记空白卷」校准阈值，或手动调节滑块 |
| 填空题答案错位 | 使用「多区域框选」，每个空位单独框选，带编号标签 |
| 印刷文字被当作答案 | 提示词已指导 AI 区分印刷文字和手写内容 |
| 填分失败 | 检查按钮位置配置 |
